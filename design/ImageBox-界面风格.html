YPuddin ImageBox · 界面风格提案

同一个下载场景，四种界面风格

四套样稿画的是同一刻：在 Danbooru 按画师组合条件、估算命中数，队列里还有别的任务在跑。功能骨架相同，差别在布局、信息密度和视觉语言。样稿里的画师、帖子编号和数字都是示例，缩略图由程序生成。

四套共用的功能骨架

  • 下载条件按画师、tag、Pool 或 Post ID；分级、分数、尺寸、日期、格式；先估算命中再下载
  • 订阅画师或查询定时检查，只下载新作
  • 队列并发下载与限速，遇到 429 自动退避，失败可重试
  • 图库本地索引与 md5 去重，按画师、来源、分级、tag 筛选，可导出训练集
  • 设置各平台账号与 API Key、代理、限速、保存位置与命名规则

A

工坊 · 与训练器同源

直接沿用 AnimaLoraStudio 的设计语言：暖白底、克制的橙色、紧凑的技术控件。三栏布局，左边是导航和各平台状态，中间是条件表单与结果预览，右边是队列和日志。

暖白 #f6f5f1 卡片 #ffffff 墨 #1a1812 橙 #d8541d 成功 #2d7a4f

字体系统无衬线 + 等宽，与训练器相同

看点

  • tag 额度条：免费账号服务端只能用 2 个 tag，排除项、尺寸和格式自动转为本地过滤
  • 估算按「服务端命中 → 本地过滤后 → 已在图库 → 待下载」逐级列出，下多少一目了然
  • 与训练器共用组件和配色 token，两个软件来回切换不用重新适应

适合

  • 同时在用训练器，希望两边操作习惯一致
  • 经常做条件复杂的批量下载

代价

  • 看图区域小，浏览图库的体验一般
  • 工具感强，视觉上没有新鲜感
B

夜幕画廊 · 看图优先

图是主角：深色底、瀑布流大图，条件都收进顶部搜索框里，变成一个个可点的标签。多选后从底部浮条下载，右侧详情按 Danbooru 的 tag 分类着色，并附中文释义。

墨夜 #0e0f14 面板 #1b1e27 月白 #eceef5 樱粉 #ff8fb3 画师红 #ff8a8b

字体Manrope + 系统中文

看点

  • 条件就是搜索框里的标签，点开能改，点叉能删
  • 瀑布流直接标出「已有」，多选后从底部浮条下载，队列进度也在浮条里
  • 详情按画师、作品、一般、元四类着色，颜色与 Danbooru 一致

适合

  • 下载后要大量浏览、挑图、整理图库
  • 习惯在深色界面里看图

代价

  • 日期、分数这类条件收在标签里，不如表单直观
  • 大图瀑布流对缩略图缓存和内存的要求更高
C

查询终端 · 键盘优先

给熟悉 booru 语法的人：条件直接写成查询，边写边补全、边检查。右边是执行计划，写清哪些条件发给服务端、哪些在本地过滤；下面是结果表、限速器和日志。

石墨 #0d1015 编辑区 #11151c 青 #45d0c0 一般 tag #79b8ff 元标签 #ffa657

字体JetBrains Mono，全局等宽

看点

  • 直接写 booru 语法，补全带中文释义和帖子数，@ 开头的是本地过滤指令
  • 实时检查：超出 tag 上限、语法错误在输入时就提示
  • 执行计划、限速器、日志放在一屏里，被限速或失败时能直接看出原因

适合

  • 熟悉 rating:、score:>= 这类元标签
  • 经常跑大批量任务，需要排查限速和失败

代价

  • 新手门槛最高
  • 看图体验最弱；语法解析、补全和检查的开发量最大
D

布丁 · 引导式

YPuddin 的品牌版：奶油、卡士达和焦糖色，大圆角和带厚度的按钮。新建下载拆成四步问答，常用条件做成开关；订阅做成画师卡片，新作数量直接挂在卡片上。

奶油 #fdf6e9 卡士达 #ffd978 焦糖 #a8622a 樱桃 #e2566a 薄荷 #3f9f7f

字体Fredoka + 系统中文

看点

  • 四步问答完成一次下载，常用条件是开关，不会写 tag 也能用
  • 订阅是画师卡片，新作数量、检查频率、开关都在一行
  • 限速时说人话：「站点限速，38 秒后自动继续」

适合

  • 偶尔下载，不想记语法
  • 以后打算给别人用的公开版本

代价

  • 信息密度最低，重度使用时点击次数多
  • 复杂查询需要单独做一个「高级模式」

下载内核：沿用 AnimaLoraStudio

训练器 studio/services/booru/ 里的做法可以整体搬过来，四套界面都建在这一层之上。

已经有的

  • Gelbooru 走 index.php?page=dapi&s=post&q=index&json=1，每页最多 100 条，页码 pid 从 0 开始，带 user_id + api_key
  • Danbooru 走 posts.json，每页最多 200 条，HTTP Basic 认证（用户名 + API Key）
  • 统一抽取 id、原图地址、尺寸和 tag，兼容 Gelbooru 的 @attributes 嵌套
  • User-Agent 用「应用名/版本 (by 用户名)」通过 Cloudflare，浏览器 UA 和默认 UA 都会被 403
  • 双令牌桶限速：接口 2 次/秒、图床 5 次/秒，4 线程并发；429 退避 60 秒并减半速率，503 退避 15 秒
  • 单图失败重试 3 次（间隔 1 / 2 / 4 秒），翻页间隔 1 秒，随时可取消
  • 命中数估算：Gelbooru 读 @attributes.count，Danbooru 调 counts/posts.json
  • 全局排除 tag、HTTP / SOCKS 代理、中文 tag 词典与补全

新软件要补的

  • 按画师下载与订阅：记住上次最大的 post id，定时只拉新作
  • 本地元数据库：md5 去重，按画师、来源、分级、tag 建索引；训练器目前按文件名判断是否已下载
  • 默认保存原始文件；转 PNG、去透明通道挪到「导出训练集」时再做
  • Danbooru 免费账号一次只能搜 2 个 tag（Gold 6 个、Platinum 12 个），超出的条件改为本地过滤
  • 来源做成可插拔，后续接 Yande.re、Konachan 等
